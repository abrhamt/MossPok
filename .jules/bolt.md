## 2024-06-11 - React.memo with Custom Comparison for Presentational Game Components
**Learning:** Frontend presentational game components (like `PokerCard`) often receive nested inline object props (e.g., `card={ { suit, rank } }`) from parent container arrays. This object reference changing on every parent render causes expensive component re-renders even when the underlying data (suit/rank) hasn't changed. Standard `React.memo` is insufficient because the shallow prop comparison fails on new object references.
**Action:** When memoizing purely presentational components that receive inline objects in this codebase, always use `React.memo` with a custom comparison function that manually diffs the semantically important primitive values (e.g., `prevProps.card.suit === nextProps.card.suit`).
